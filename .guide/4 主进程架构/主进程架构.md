# DSH Desktop 主进程架构

## 启动流程

```
Electron main.ts
  → 获取单实例锁
  → 读取 profile/mode 状态
  → Launcher 准备激活 profile
  → 提供 native runtime + desktopProfiles bootstrap + pnpm 环境
  → Host Cordis root 启动 Loader entries
  → Desktop service 注册（在第三方插件之前）
  → 官方 dsh-base + dsh-web-app + 第三方 bundle 组成 Web carrier
  → Host 绑定 loopback（或所有网络接口）
  → Electron 创建 BrowserWindow，加载 loopback 页面
  → Web surface 加载成功 → 创建托盘 → 提交 last-known-good 状态
```

## 核心模块

| 模块 | 文件 | 职责 |
|:--|:--|:--|
| 入口 | `main.ts` | Electron 启动入口 |
| Electron 运行时 | `electron-runtime.ts` | 协调 Host 与原生环境 |
| Shell Generation | `electron-shell-generation.ts` | 窗口/托盘的 generation 生命周期 |

## 平台适配

平台差异集中在 `ElectronPlatformStrategy` seam：

| 平台 | 能力 |
|:--|:--|
| Windows | 目录选择、Shell 模式、NSIS 安装器、ACL 沙箱、PowerShell 沙箱 |
| macOS | 目录选择、Dock 图标、Universal 二进制、Hardened Runtime、公证 |
| Linux | 目录选择、基本 Shell 模式 |

## Generation 模型

每次 profile/模式切换都会：
1. `dispose()` 当前 generation
2. 启动新 generation

**不允许跨 generation 缓存**：Service reference、窗口对象、subprocess handle 都不能跨 generation。

## IPC 通信

- Desktop **不使用** renderer IPC 插件系统
- Host 通过 HTTP/WebSocket Web carrier 与 Renderer 通信
- Desktop 级确认、警告、错误使用独立 `DesktopDialogWindow`（沙箱化 BrowserWindow）
