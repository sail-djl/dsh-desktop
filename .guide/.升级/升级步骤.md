# DSH Desktop 升级指南：vendored runtime alpha.1 → alpha.4

> 本文档记录 dsh-desktop 从 vendored runtime alpha.1 升级到 alpha.4 的完整步骤，包括 Git 操作、依赖修复、本地构建打包。

## 1. 升级背景

- 上游 DeepSeek Harness 发布了 `dsh-v0.1.2-alpha.4`，需要将 vendored runtime 从 `alpha.1` 升级到 `alpha.4`
- 同时需要将远程仓库从 `anywhere-labs/dsh-desktop` 切换到 `sail-djl/dsh-desktop` 作为 origin
- master 分支保持干净，升级代码在 feature 分支上

## 2. 前置条件

| 依赖 | 版本要求 | 说明 |
|:--|:--|:--|
| Node.js | `^22.19.0` 或 `>=24.0.0` | 构建脚本硬性要求，26.x 不兼容 |
| Yarn | 4.18.0（Corepack） | 根 workspace 包管理 |
| Git | 最新 | 子模块 + 远程操作 |
| 网络 | 能访问 npmmirror | Electron 二进制下载 |

## 3. Git 操作

### 3.1 切换远程仓库

```bash
# 将原 origin 重命名为 upstream
git remote rename origin upstream

# 添加 sail-djl 作为新 origin
git remote add origin https://github.com/sail-djl/dsh-desktop.git
```

最终 remote 配置：

| 别名 | 地址 |
|:--|:--|
| `origin` | `https://github.com/sail-djl/dsh-desktop.git` |
| `upstream` | `https://github.com/anywhere-labs/dsh-desktop.git` |

### 3.2 创建 feature 分支

```bash
# 确保 master 与 upstream 同步
git fetch upstream
git checkout master
git reset --hard upstream/master

# 创建升级分支
git checkout -b feat/vendored-alpha.4
```

### 3.3 升级 vendored runtime

vendored runtime 的升级涉及两个层面：

1. **vendor 目录**：替换 `vendor/dsh-runtime/0.1.2-alpha.1/` 下的 tgz 包为 `0.1.2-alpha.4` 版本
2. **package.json resolutions**：根 `package.json` 的 `resolutions` 字段将所有 `@deepseek-ai/dsh-*` 包指向新的 tgz 路径

关键 commit：

```
bdcbab51e1  chore: upgrade vendored runtime from alpha.1 to alpha.4
2c8a0d0b0b  chore: pin upstream submodule to dsh-v0.1.2-alpha.4
```

### 3.4 推送到 origin

```bash
git push -u origin feat/vendored-alpha.4
```

### 3.5 保持 master 干净

```bash
git checkout master
git reset --hard upstream/master
```

## 4. 依赖修复

升级后 `verify:closure` 检查发现缺失依赖：

```
verify-runtime-closure: required first-party peers are missing from dsh-plugin-desktop dependencies:
  dsh-plugin-desktop -> @deepseek-ai/dsh-api-session-controller -> @deepseek-ai/dsh-util-time
  dsh-plugin-desktop -> @deepseek-ai/dsh-subagent -> @deepseek-ai/dsh-util-time
```

**修复**：在 `dsh-plugin-desktop/package.json` 的 `dependencies` 中添加：

```json
"@deepseek-ai/dsh-util-time": "0.1.2-alpha.4"
```

添加位置：在 `@deepseek-ai/dsh-util-crypto` 和 `@deepseek-ai/dsh-util-workspace-path` 之间（按字母序）。

然后重新安装依赖：

```bash
corepack yarn install
```

> 注意：不能使用 `--immutable`，因为 lockfile 需要更新。

## 5. Node.js 版本切换

构建脚本 `dsh-plugin-desktop/scripts/package-win.ts` 硬性检查 Node 版本：

```typescript
if (!((major === 22 && minor >= 19) || major === 24)) {
  throw new Error(
    `Windows ${artifact} requires Node 22.19+ or Node 24.x with bundled Corepack; received ${options.nodeVersion}`,
  )
}
```

如果当前 Node 版本不满足（如 26.x），需要切换：

```bash
# 安装 Node 22.x
nvm install 22

# 切换到 22.x（需要管理员权限）
nvm use 22.23.2

# 验证
node --version  # 应显示 v22.23.2
```

## 6. 构建打包

### 6.1 设置 Electron 镜像（国内网络必需）

electron-builder 默认从 GitHub CDN 下载 Electron 二进制，国内网络会超时。需要设置镜像：

```powershell
$env:ELECTRON_MIRROR = "https://cdn.npmmirror.com/binaries/electron/"
```

### 6.2 执行完整构建

```bash
corepack yarn dist:win
```

此命令会依次执行：

1. `dsh-community-market` 构建
2. `dsh-plugin-desktop` 构建（tsdown + vite + tsc）
3. 单元测试（186 个测试）
4. `verify:closure` 运行时闭包检查
5. `verify:cli` / `verify:loader` / `verify:profile` 等验证
6. electron-builder 打包 NSIS 安装器
7. 安装器验证

### 6.3 产物

| 产物 | 路径 | 说明 |
|:--|:--|:--|
| NSIS 安装器 | `dsh-plugin-desktop/dist/DSH-Desktop-2.0.4-x64-Setup.exe` | 标准安装器 |
| 解压目录 | `dsh-plugin-desktop/dist/win-unpacked/` | 未打包的应用 |

## 7. 构建过程中常见问题

### 7.1 Node 版本不兼容

**错误**：`Windows installer requires Node 22.19+ or Node 24.x with bundled Corepack; received 26.8.1`

**解决**：使用 nvm 切换到 Node 22.x（见第 5 节）。

### 7.2 verify:closure 缺失依赖

**错误**：`verify-runtime-closure: required first-party peers are missing`

**解决**：在 `dsh-plugin-desktop/package.json` 中添加缺失的依赖包（见第 4 节）。

### 7.3 Electron 下载超时

**错误**：`connect ETIMEDOUT 20.205.243.166:443`

**解决**：设置 `ELECTRON_MIRROR` 环境变量使用国内镜像（见第 6.1 节）。

### 7.4 lockfile immutable 失败

**错误**：`The lockfile would have been modified by this install, which is explicitly forbidden.`

**解决**：添加新依赖后不能使用 `--immutable`，直接运行 `corepack yarn install`。
