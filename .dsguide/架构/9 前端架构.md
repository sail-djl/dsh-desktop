## 核心架构

### Cordis 微内核

Cordis 是插件化框架内核，只负责：
- 插件的加载和卸载
- 插件依赖管理
- 类型化事件系统
- 可逆效果（卸载时回滚）

### 插件化设计

每个能力都是独立包，提供三种角色：
- **Service Definition**：声明接口
- **Service Provider**：实现接口
- **Consumer**：使用接口（通常是模型面向的工具）

### 包结构概览

| 包 | 职责 | ctx key |
|:--|:--|:--|
| `core/session` | append-only SessionEvent 日志 | `ctx.sessions` |
| `core/system-prompt` | 提示词组装 | `ctx.systemPrompt` |
| `core/tools` | 工具注册和执行管线 | `ctx.tools` |
| `core/agent` | Agent 接口和事件 | `ctx.agents` |
| `core/agent-loop` | 默认驱动实现 | `ctx.agentLoop` |
| `llm/llm` | 消息词汇和适配器 | `ctx.llm` |

## 事件系统

### 三类事件

1. **Session Events**：持久化事实，写入日志
2. **Agent Events**：实时 Agent 状态（inbox, step, status）
3. **Capability Events**：策略和适配器绑定（fs, tools, telemetry）

### Turn 流程

```
turn/start → claim input → assemble prompt
  → agent/pre-step (可拒绝/重写)
    → step/start → append user/message
      → agent/request → llm/stream → assistant/message
      → tool/call* → tools/execute → tool/result*
    → step/end
  → agent/turn-stopping
turn/end
```

## 构建架构

### 双聚合 TypeScript

- **Host 聚合**：服务端代码
- **Client 聚合**：客户端代码
- 两者独立构建，避免 Context 接口合并冲突

### 构建顺序

```
tsc (host) → tsdown (host) → tsc (client) → tsdown (client) → vite build (web)
```

## 运行模式

| 模式 | 说明 |
|:--|:--|
| Standard | 完整工具集（文件编辑、Shell、搜索、技能、计划等） |
| Code | 模型生成代码编排多轮工具调用 |
| Minimal | 仅 Shell + 文件编辑器 |
| Creator | 运行时检查 + 插件实验 + 预设编写 |
