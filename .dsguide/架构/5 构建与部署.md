# DeepSeek Harness 构建与部署

## 一、Profile 与 Bundle 机制

### 1.1 Profile（配置档案）

一个运行中的 dsh 是启动时从有序层组成的插件树。

- 存储在 `$DSH_HOME/profiles/<name>/`
- 包含 `package.json`（out-of-tree 插件依赖 + `dsh.profile.bundles` 列表）
- 包含用户自己的 `cordis.patch.yml`
- 内置模板：`web` 和 `headless`

### 1.2 Bundle（分发格式）

npm 包，manifest 声明：
```json
{
  "dsh": {
    "bundle": {
      "patch": "./cordis.patch.yml"
    }
  }
}
```

三个核心 bundle：
| Bundle | 作用 |
|:--|:--|
| `dsh-base` | 每个 profile 的第一层：模型适配器、工具、持久化、沙箱、设置、凭据、遥测 |
| `dsh-web-app` | 添加浏览器应用层 |
| `dsh-headless` | 添加无服务器的一次性任务运行器 |

### 1.3 层级应用顺序

1. Profile 中列出的 bundle 按序
2. Profile 的 `cordis.patch.yml`
3. Home 级别的 `cordis.patch.yml`
4. 任何 `--patch` overlay

Patch 通过 id 定位 config row，替换其整个 `config` 或插入新行。

### 1.4 查看当前配置树

```bash
dsh --profile web --dump-config
```

## 二、TypeScript 双聚合架构

### 2.1 配置文件

| 文件 | 角色 |
|:--|:--|
| `tsconfig.json` | 解决方案根，引用两个聚合 |
| `tsconfig.host.json` | Host 聚合（服务端） |
| `tsconfig.client.json` | Client 聚合（客户端） |
| `tsconfig.base.json` | 共享编译选项和 paths 映射 |
| `tsconfig.base.client.json` | 浏览器编译设置（JSX, DOM） |

### 2.2 为什么分离

Host 和 Client 声明合并了 cordis `Context` 接口下的相同 key，但有不同的服务。一个程序看到两个合并会报告冲突。分离后：
- 模块解析不触发冲突
- 每个包注册到恰好一个 aggregate

### 2.3 构建顺序

```
tsc -b tsconfig.host.json        # 编译 Host
tsdown --env.DSH_BUILD_FACE host  # 打包 Host
tsc -b tsconfig.client.json      # 编译 Client
tsdown --env.DSH_BUILD_FACE client # 打包 Client
pnpm run build:web               # 构建 Web UI
```

### 2.4 关键约束

- `tsconfig.base.json` 永远不加 `include` 或 `files`
- 新包只能注册到一个 aggregate
- `api/remotes` 是唯一 split 的包（Host 和 Client 各有 tsconfig）

## 三、Vendor 机制

`vendor/` 包含 Cordis 框架和基础库的源码 vendor 副本（带上游 SHA），通过同步程序更新。

| Vendor 包 | 说明 |
|:--|:--|
| `cordis/` | 插件化微内核 |
| `cosmokit/` | 工具库 |
| `group/` | 分组 |
| `hmr/` | 热更新 |
| `loader/` | 配置加载器 |
| `schemastery/` | Schema 验证 |
| `timer/` | 定时器 |

---

## 四、环境变量

| 变量 | 必填 | 说明 |
|:--|:--|:--|
| `DEEPSEEK_API_KEY` | 是 | DeepSeek API 密钥 |
| `DEEPSEEK_BASE_URL` | 否 | 自定义 API 地址 |

凭据优先级：进程环境变量 > `.credentials.yaml` > `.env`

## 五、发布流程

```bash
# 版本发布
pnpm run release:dsh           # bump 版本
pnpm run release:verify        # 验证
pnpm run release:pack          # 打包
pnpm run release:publish       # 发布到 npm
```
