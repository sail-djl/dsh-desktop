## 二、核心概念

### 2.1 Cordis — 一切皆插件

DSH 构建在 **Cordis** 微内核之上。产品中的每一个组件（模型适配器、工具注册表、会话日志、Agent 循环本身）都是插件。没有特权核心；通过挂载新插件扩展，卸载时自动回退。

| 概念                         | 说明                                                                                     |
| :--------------------------- | :--------------------------------------------------------------------------------------- |
| **插件即 Service**     | 实现`Service` 的对象；可以是带 `inject` + `apply(ctx)` 的函数，或 `Service` 子类 |
| **Context 即服务仓库** | 插件通过`ctx.<key>`（如 `ctx.tools`、`ctx.llm`）声明依赖                           |
| **inject 声明依赖**    | 命名所需服务后，Cordis 等待这些服务存在再激活                                            |
| **类型化事件通信**     | 通过 TypeScript 声明合并定义事件名，`emit`/`waterfall`/`parallel`/`serial` 分发  |
| **注册即可逆效果**     | 通过`ctx.effect()` / `ctx.on()` 安装的组件在卸载时自动回退                           |

### 2.2 Capability Seam（能力接缝）

每个可替换能力由三个角色组成：

```
Service Definition (ctx.<key>)    ← 声明接口
        ↓
Service Provider                   ← 实现能力
        ↓
Consumer (面向模型的工具)          ← 使用能力
```

典型例子 — Shell：

- `dsh-shell` = Service Definition（`ctx.shell`）
- `dsh-bash-local` / `dsh-bash-sandbox` = Provider
- `dsh-tool-bash` = Consumer

### 2.3 Scope（作用域）

每个 Agent 拥有自己的 scoped context（`agent.ctx`），支持：

- **注册隔离**：通过 `agent.ctx` 的注册只对该 Agent 可见
- **事件过滤**：通过 `scopeTarget()` 路由事件
- **父子链**：子 scope 可以看到祖先的注册

## 三、事件系统

### 3.1 分发模式

| 模式          | 等待? | 执行顺序                | 有返回值? |
| :------------ | :---- | :---------------------- | :-------- |
| `emit`      | 否    | listener 按注册顺序观察 | 否        |
| `waterfall` | 否    | around-middleware 模式  | 是        |
| `parallel`  | 是    | 所有 listener 并行      | 否        |
| `serial`    | 是    | listener 按注册顺序     | 是        |

### 3.2 事件分类

| 类别                 | 事件                                                             | 说明            |
| :------------------- | :--------------------------------------------------------------- | :-------------- |
| **Session**    | `turn/start`, `turn/end`, `step/start`, `step/end`       | Turn/Step 边界  |
|                      | `user/message`, `assistant/chunk`, `assistant/message`     | 消息流          |
|                      | `tool/call`, `tool/result`                                   | 工具调用        |
| **Agent**      | `agent/created`, `agent/disposed`                            | 生命周期        |
|                      | `agent/pre-step` (waterfall)                                   | 拒绝或替换 step |
|                      | `agent/request` (waterfall)                                    | 替换调用配置    |
| **Capability** | `tools/pre-execute`, `tools/execute`, `tools/post-execute` | 工具管线        |
|                      | `llm/stream` (waterfall)                                       | 模型调用        |
|                      | `system-prompt/assemble` (waterfall)                           | Prompt 装配     |
|                      | `fs/write-intent`, `fs/observed`                             | 文件系统        |

## 四、Turn 流程

```
Round（策略迭代）
  └── Turn（一次输入消耗）
        └── Step（一次模型请求 + 工具执行）
```

完整流程：

```
turn/start
  claim next-step input
  assemble prompt sections + tool schemas
  → agent/pre-step              reject | enter(messages)
    step/start
    append user/message
    derive model history
    agent/request → llm/stream → assistant/chunk* → assistant/message
    tool/call* → tools/pre-execute → tools/execute → tools/post-execute → tool/result*
    step/end
    → agent/turn-stopping
turn/end
```

## 七、构建架构

### TypeScript 双聚合

```
tsconfig.base.json       共享编译选项
tsconfig.base.client.json 浏览器编译设置
tsconfig.host.json       Host 聚合（服务端）
tsconfig.client.json     Client 聚合（客户端）
```

构建顺序：

```
tsc (host) → tsdown (host) → tsc (client) → tsdown (client) → vite build (web)
```
