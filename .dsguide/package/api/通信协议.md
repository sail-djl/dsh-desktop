# 通信协议 — Typert RPC 远程调用机制

## 架构总览

```
┌─────────────────────────────────────────────────┐
│                   Client Side                     │
│                                                   │
│  ctx.remote.$mount()                              │
│    ├─ 注册生成的 Host-for-Client 贡献项            │
│    ├─ 安装 direct 方法（remote.ns.method()）       │
│    └─ 安装 scoped 方法（remote.ns.scope.method()）│
│                                                   │
│  ctx.connection.rpc.call('/api', endpoint, args)  │
│    └─ 通过 Connection 发送 RPC 请求               │
└─────────────────────┬───────────────────────────┘
                      │ HTTP / WebSocket
                      ▼
┌─────────────────────┴───────────────────────────┐
│                   Host Side                       │
│                                                   │
│  Connection rpc.intercept('/api', ...)            │
│    ├─ claimsEndpoint() → 判断是否 Gateway 负责    │
│    └─ dispatchRpc() → 转发给 Gateway              │
│                                                   │
│  ctx.typertGateway.invoke({                       │
│    namespace, method, args, signal                │
│  })                                               │
│    ├─ resolveDescriptor()  ← 严格 or SRC          │
│    ├─ assertExactArguments()                      │
│    ├─ resolveReceiverContext()  ← Context 解析    │
│    ├─ resolveParameter()  ← Lookup 参数解析       │
│    └─ Reflect.apply(method, receiver, args)       │
│                                                   │
│  返回校验后的结果                                  │
└─────────────────────────────────────────────────┘
```

## InvocationDescriptor 结构

```typescript
interface InvocationDescriptor {
  id: string                          // 唯一标识
  service: string                     // Cordis 服务 key
  namespace: string                   // Remote 命名空间
  method: string                      // 方法名
  implementation?: string             // 实际实现方法名（与导出名不同时）
  invocation: {
    kind: 'direct' | 'context'        // 直接调用 or Context 身份解析
    context?: string                  // Context provider 名
    wire?: string                     // wire 字段名
    codec?: TypertCodec               // 编解码器
  }
  parameters: InvocationParameterDescriptor[]  // 参数描述
  cancellation?: { parameter: string }          // 取消参数
  result: TypertCodec                          // 返回值编解码器
}
```

## Lookup 机制

Remote 方法的参数可以是：
- **JSON 参数**：直接从 wire 值解码
- **Lookup 参数**：通过 `ctx.typert.lookups` 中的 provider 解析身份

```
Client 发送 args: { agentId: "abc" }
  │
  ├─ Gateway.resolveParameter()
  │    ├─ parameter.source === 'lookup'
  │    ├─ ctx.typert.lookups.get('agent')
  │    └─ provider.resolve(agentId) → Agent 实例
  │
  └─ 注入解析后的对象到业务方法参数
```

## Context 身份解析

`@RemoteScope` 标记的方法通过 Context provider 解析接收者：

```
Client 发送 args: { sessionId: "xyz", message: "hello" }
  │
  ├─ Gateway.resolveReceiverContext()
  │    ├─ invocation.kind === 'context'
  │    ├─ ctx.typert.contexts.getHost('session')
  │    └─ provider.resolve(sessionId) → Session Context
  │
  └─ 在该 Context 上调用方法
```

## 取消机制

支持取消的 Remote 方法把 `signal: AbortSignal` 声明为最后一个 Host 参数：

```
Client: ctx.remote.ns.method(args, signal)
  │
  ├─ Gateway 注入 signal 到业务方法末尾
  ├─ 业务方法执行中...
  ├─ signal.abort() 触发
  └─ RemoteInvocationCancelled → RPC cancelled
```

## 事件转发

Host 事件通过 Connection 帧泵转发给 Client：

```
Host ctx.emit('llm/adapters-updated', ...)
  │
  ├─ Connection 编码为帧
  ├─ 通过 WebSocket/HTTP 发送
  │
Client ctx.remote.$dispatch(frame)
  │
  └─ ctx.remote.$on('llm/adapters-updated', listener)
       └─ 按注册顺序投递（单向、隔离、不 replay）
```

**控制点**：`API_REMOTE_FORWARDED_EVENTS` 数组是唯一控制「消费端能收到什么」的地方

## 严格模式 vs SRC 模式

| 特性 | 严格模式 | SRC 模式 |
|:--|:--|:--|
| 描述符来源 | `ctx.typert.local.get(endpoint)` | 反射 `@Remote` 标记 |
| 参数校验 | Zod schema 解析 | 仅 JSON 安全性 |
| 类型安全 | 完整 TypeScript 类型 | 运行时参数名 |
| Client 支持 | 完整编解码器 | 不支持 |
| 撤回行为 | 禁止回退到 SRC | N/A |
| 用途 | 生产环境 | 开发回退路径 |
