# 包详解 — gateway 和 remotes

## 1. dsh-api-gateway — Typert RPC 分发器

> Host 侧分发请求到 Cordis 服务，Client 侧提供类型安全代理

### Host 服务：`TypertGatewayService`（ctx key: `typertGateway`）

| 方法 | 签名 | 说明 |
|:--|:--|:--|
| `invoke` | `(request: InvokeRemoteRequest) → Promise<unknown>` | 调用一个 Remote 方法 |

**InvokeRemoteRequest 结构**：
```typescript
interface InvokeRemoteRequest {
  namespace: string          // Remote 命名空间
  method: string             // 导出的 Service 方法名
  args: Record<string, unknown>  // 命名 wire 参数
  signal?: AbortSignal       // 可选取消信号
}
```

### 调用流程

```
Client 发起 RPC 调用
  │
  ├─ Connection 接收请求
  │    └─ intercept('/api', claimsEndpoint, dispatchRpc)
  │
  ├─ Gateway.invoke()
  │    ├─ resolveDescriptor()  ← 严格模式 or SRC 回退
  │    ├─ assertExactArguments()  ← 参数校验
  │    ├─ resolveReceiverContext()  ← Context 身份解析
  │    ├─ resolveParameter()  ← lookup 参数解析
  │    └─ Reflect.apply(method, receiver, args)  ← 业务调用
  │
  └─ 返回校验后的结果
```

### 错误码（`TypertGatewayErrorCode`）

| 错误码 | 说明 |
|:--|:--|
| `ambiguous-endpoint` | 多个 Service 导出同一 endpoint |
| `arguments-invalid` | args 字段与 descriptor 不匹配 |
| `binding-invalid` | Service 没有有效的 typertRemote 绑定 |
| `context-unavailable` | Context provider 不可用 |
| `context-not-found` | Context provider 未解析到身份 |
| `definition-unavailable` | 严格定义已撤回，SRC 不允许 |
| `input-invalid` | wire 字段边界校验失败 |
| `invocation-unavailable` | 无活跃 Remote 方法导出此 endpoint |
| `lookup-unavailable` | lookup provider 不可用 |
| `lookup-not-found` | lookup provider 未解析到身份 |
| `method-unavailable` | Service 没有可调用的方法 |
| `service-unavailable` | 活跃 Service 不可用 |
| `signature-invalid` | SRC 方法签名不合法 |
| `result-invalid` | 业务结果边界校验失败 |

### Client 服务：`ClientRemote`（ctx key: `remote`）

| 方法 | 说明 |
|:--|:--|
| `ctx.remote.$mount()` | 校验并注册生成的 Host-for-Client 贡献项 |
| `ctx.remote.$on(event, listener)` | 订阅转发的 Host 事件 |
| `ctx.remote.$dispatch()` | 接收解码后的 Host 帧（载体侧） |

### 两种模式

| 模式 | 说明 | 使用场景 |
|:--|:--|:--|
| **严格模式** | 从 `ctx.typert.local` 读取生成的调用描述符，Zod schema 校验 | 生产环境 |
| **SRC 模式** | 从 `@Remote` 标记反射参数名，仅校验 JSON 安全性 | 开发回退路径 |

### 依赖

**dependencies**：`dsh-typert-protocol`
**peerDependencies**：`dsh-client-connection`, `dsh-typert-registry`, `cordis`

## 2. dsh-api-remotes — Remote BFF 组装

> 为选定的 Host Remote 能力提供双侧 BFF

### Host 入口

- `createApiRemoteAgentResolver()` — 复用 live Agent、恢复冷会话、去重并发恢复、保留 subagent ownership fence
- `inspectApiRemoteSession()` — Session 元数据检查
- `hasApiRemoteSubagentOwner()` — 判断是否属于 subagent ownership
- `API_REMOTE_FORWARDED_EVENTS` — 转发事件名单

### Client 入口

- 导入生成的 `/remote` 产物
- 通过 `ctx.remote.$mount()` 挂载贡献项
- 重新导出声明合并

### 转发事件名单

```typescript
const API_REMOTE_FORWARDED_EVENTS = [
  'agent-preset/selected',        // agent preset 选择
  'commands/change',              // 命令变更
  'credentials/reference-updated', // 凭据引用更新
  'cordis/request-run',           // Cordis 请求运行
  'cordis/request-run-resolved',  // Cordis 请求运行解析
  'cordis/dynamic-package',       // 动态包
  'cordis/dynamic-retract',       // 动态撤回
  'cordis/inspect-query',         // 检查查询
  'cordis/inspect-query-resolved', // 检查查询解析
  'llm/adapters-updated',         // LLM 适配器更新
  'settings/document-updated',    // 设置文档更新
]
```

**扩展方式**：在数组中加一行 → Host 转发循环 + Client `ctx.remote.$on` 键面自动派生

### 构建边界（唯一 split 包）

```
tsconfig.host.json ← Host 入口（src/index.ts）
tsconfig.client.json ← Client 入口（src/client/index.ts）
共享文件：src/remote-events.ts + src/types.ts（两个 face 都列出）
```

**为什么 split**：
- Host 入口要参与 Host Typert 图
- Client 入口必须等 Host tsdown 生成业务包的 `/remote` 声明后才能编译
- 转发事件名单是「消费端能收到什么」的唯一控制点，Host 和 Client 必须读同一份
