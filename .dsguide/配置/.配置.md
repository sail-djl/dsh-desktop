## 配置体系架构

DSHarness 采用**两层配置体系**：

1. **组合配置 (Composition Config)**：通过 Cordis Loader 的 `cordis.patch.yml` 多层补丁实现插件级配置
2. **用户设置 (User Settings)**：通过 `ctx.settings` 服务，存储在 `$DSH_HOME/settings.yaml`，支持热重载

### 补丁层叠加顺序（后覆盖前）

| 优先级 | 层级 | 来源 |
|:--|:--|:--|
| 1 | Bundle 层 | `package.json` `dsh.profile.bundles` 列出的包的 `cordis.patch.yml` |
| 2 | Profile 用户层 | `$DSH_HOME/profiles/<name>/cordis.patch.yml` |
| 3 | Home 用户层 | `$DSH_HOME/cordis.patch.yml`（机器级别偏好） |
| 4 | --patch 叠加层 | 命令行 `--patch <path>` 指定的文件 |
| 5 | 遥测开关 | `DSH_TELEMETRY_DISABLED` 环境变量 |

> **重要**：patch 替换整行的 `config`（非深度合并），最后一个写入者赢。

## Profile 配置

| Profile | 说明 |
|:--|:--|
| `web` | Web UI 模式（含完整 Web 服务器、浏览器客户端） |
| `headless` | 无服务器的一次性运行模式（回答一个任务后退出） |
| `tui` | 终端 UI 模式（插件注册，详见各 profile cordis.patch.yml） |
| `sdk` | SDK 模式（独立完整 Cordis 树） |
| `sdk-minimal` | 最小 SDK 模式 |
| `acp` | ACP 自动化应用模式 |

### Profile 文件位置

- 源码版：`$DSH_HOME/profiles/<name>/cordis.patch.yml`
- 内置包：`packages/bundle/<name>/`

## 用户设置（settings.yaml）

用户可通过 `$DSH_HOME/settings.yaml` 配置以下命名空间（热重载，无需重启）：

| 命名空间 | 说明 | 生效时机 |
|:--|:--|:--|
| `llm-deepseek` | DeepSeek LLM 适配器配置 | live |
| `llm-pi-ai` | Pi-AI 多提供方 Provider Profiles | live |
| `subagent-model-selection` | 子代理模型选择 | restart |

### 设置解析顺序

```
schema 默认值 → composition base → 用户文档层（后者覆盖前者）
```

## 源码启动配置（.dsh/startup.yaml）

> 设计方案见 [启动配置系统.md](./启动配置系统.md)
> 仅开发环境使用，优先级：CLI 参数 > `~/.dsh/startup.yaml` > 此文件 > 默认值

```yaml
env: dev               # dev | test | prod

dsh:
  root: "<项目根路径>"  # 源码根目录
  port: 5300           # Web 服务端口
  profile: web         # 默认 profile

api:
  deepseek_key: "${DEEPSEEK_API_KEY}"
  deepseek_base_url: null

runtime:
  open_browser: false
  log_level: info      # debug | info | warn

environments:
  dev:
    runtime:
      log_level: debug
  test:
  prod:
    runtime:
      log_level: warn
      open_browser: true
```

## 注意事项

- 配置补丁 patch 替换整行 config（非深度合并），不同 mode 的值应分别放在各自 bundle 层
- `settings.yaml` 支持热重载（写入后自动生效，无需重启）
- `cordis.patch.yml` 中的 `!!js` 表达式会被 Loader 求值（可引用 `process.env.*`、`ctx.*`、`dshHomePath()` 等）
- Windows 下 `bash-sandbox` 和 `tool-bash` 自动禁用，改用 `pwsh-sandbox` 和 `tool-pwsh`
- Agent 预设（Presets）在 Web 模式下接管工具注册，基座的 host 平面工具行会被 `disabled: true`
- `$DSH_HOME/.agent-presets` 用于自定义 Agent 预设，等同 shell 访问权限
