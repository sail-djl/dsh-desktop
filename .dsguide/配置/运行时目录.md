# DSH 运行时目录结构

## 一、工作空间（Workspace）

用户在 Web UI 中选择的工作目录，Agent 在此目录下执行文件操作。

- **选择方式**：Web UI 启动后通过 `ctx.directoryPicker` 选择
- **隔离性**：每个会话绑定一个工作区，文件系统工具受限于工作区范围
- **沙箱模式**：进一步隔离文件访问权限

```
<workspace>/                      ← 用户选择的工作目录
├── .dsh/                         ← 项目级 DSH 配置（可选）
│   ├── skills/                   ← 项目级 Skill（官方支持）
│   └── startup.yaml              ← 项目级启动配置（二开定义）
└── AGENTS.md                     ← 项目级 Agent 指令（官方支持）
```

---

## 二、主目录（DSH Home）

DSH 主目录默认为 `~/.dsh`，可通过环境变量 `$DSH_HOME` 覆盖。

```
~/.dsh/                          ← DSH_HOME（主目录根）
```

### 解析优先级

```
命令行配置 > $DSH_HOME > ~/.dsh
```

---

## 三、主目录核心文件/文件夹

```
~/.dsh/
│
├── settings.yaml                ← 用户设置（支持热重载，无需重启）
├── cordis.patch.yml             ← Home 用户级补丁（机器级偏好）
├── .credentials.yaml            ← 凭据存储（provider-managed，可写）
├── .env                         ← 环境变量回退（只读）
├── .anonymous-user-id           ← 匿名用户 ID（遥测/反馈用）
├── AGENTS.md                    ← 用户全局 Agent 指令
│
├── sessions/                    ← 会话日志持久化（JSONL 格式）
├── storages/                    ← JSON 后端存储（KV 存储）
├── profiles/                    ← Profile 目录
│   ├── <name>/                  ← 各 Profile 目录
│   │   └── cordis.patch.yml     ← Profile 用户级补丁
│   └── node_modules/            ← Profile 插件安装位置
├── .agent-presets/              ← 用户自定义 Agent 预设
└── skills/                      ← 用户自定义 Skill
```

---

## 四、各目录/文件说明

### 4.1 配置文件

| 文件                  | 用途                             | 特性                       |
| :-------------------- | :------------------------------- | :------------------------- |
| `settings.yaml`     | LLM 适配器、子代理模型选择等     | 热重载，写入即生效         |
| `cordis.patch.yml`  | 机器级配置补丁（覆盖 bundle 层） | 需重启                     |
| `.credentials.yaml` | API Key 等凭据（Provider 管理）  | 跨进程写锁，外部编辑热生效 |
| `.env`              | 环境变量回退                     | 只读，优先级最低           |
| `AGENTS.md`         | 全局 Agent 行为指令              | 自动合并到 system prompt   |

### 4.2 数据目录

| 目录                 | 用途               | 格式                            |
| :------------------- | :----------------- | :------------------------------ |
| `sessions/`        | 会话事件日志       | JSONL（每行一个 SessionEvent）  |
| `storages/`        | KV 存储后端        | JSON 文件                       |
| `profiles/<name>/` | Profile 配置与插件 | cordis.patch.yml + node_modules |
| `.agent-presets/`  | 用户自定义预设     | cordis.yml 文件                 |
| `skills/`          | 用户自定义 Skill   | SKILL.md 文件                   |

## 五、补丁叠加层级

配置补丁按以下顺序叠加（后覆盖前）：

| 优先级 | 层级           | 来源                                           |
| :----- | :------------- | :--------------------------------------------- |
| 1      | Bundle 层      | `packages/bundle/*/cordis.patch.yml`         |
| 2      | Profile 用户层 | `$DSH_HOME/profiles/<name>/cordis.patch.yml` |
| 3      | Home 用户层    | `$DSH_HOME/cordis.patch.yml`                 |
| 4      | --patch 叠加层 | 命令行`--patch <path>` 指定                  |

> **重要**：patch 替换整行 config（非深度合并），最后一个写入者赢。

---

## 六、凭据优先级

凭据解析顺序（高到低）：

```
继承的进程环境变量（只读，最高优先）
> $DSH_HOME/.credentials.yaml（provider-managed，可写）
> <cwd>/.env（只读回退）
> $DSH_HOME/.env（只读回退）
```
