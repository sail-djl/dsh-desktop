# DSH 启动配置系统设计计划

## 一、业务背景

**用户痛点**：当前 `dsh-start.ps1` 将所有配置硬编码在脚本中（Redis 连接参数、端口、patch 路径等），每次新增配置参数都需要修改脚本，不优雅且难维护。

**目标**：设计一个基于 YAML 配置文件的启动配置系统，支持分层覆盖、多环境切换、敏感信息保护。

---

## 二、配置文件格式：YAML

与 DSH 现有 `settings.yaml`、`cordis.yml` 保持一致。

---

## 三、分层配置架构

### 3.1 优先级（从高到低）

```
1. 命令行参数 --env dev/test/prod
2. 项目级 .dsh/startup.yaml（可提交到 git）
3. 用户级 ~/.dsh/startup.yaml（本地覆盖，不提交）
4. 默认值（内置在脚本中）
```

### 3.2 文件位置

| 文件 | 路径 | 用途 |
|:--|:--|:--|
| 项目级 | `DeepSeekHarness/.dsh/startup.yaml` | 团队共享配置 |
| 用户级 | `~/.dsh/startup.yaml` | 个人本地覆盖（.gitignore） |

## 四、配置文件结构

```yaml
# .dsh/startup.yaml
# DSH 启动配置 - 支持分层覆盖

# --- 环境选择 ---
env: dev  # dev | test | prod

# --- DSH 核心 ---
dsh:
  root: "E:/baizhoucode/companyagent/DeepSeekHarness"
  port: 3080
  profile: web
  patch: "E:/baizhoucode/companyagent/dsworkspace/redis-5.0.3-config.cordis.yml"

# --- Redis 连接 ---
redis:
  url: "redis://192.168.1.98:6379"
  password: "bz@2026++"
  db: 0
  connect_timeout: 10000
  command_timeout: 5000

# --- API 配置 ---
api:
  deepseek_key: "${DEEPSEEK_API_KEY}"  # 从环境变量引用
  deepseek_base_url: null  # null = 使用默认

# --- 运行时配置 ---
runtime:
  open_browser: false
  log_level: info  # debug | info | warn | error

# --- 插件配置 ---
plugins:
  enabled:
    - dsh-file-explorer
    - dsh-univer-office
    - dsh-easyssh
  disabled:
    # - dsh-ide-panel  # 已停用的插件

# --- 多环境覆盖 ---
environments:
  dev:
    redis:
      url: "redis://192.168.1.98:6379"
    runtime:
      log_level: debug
  test:
    redis:
      url: "redis://192.168.1.98:6379"
      db: 1
    runtime:
      log_level: info
  prod:
    redis:
      url: "redis://prod-server:6379"
      password: "${REDIS_PASSWORD}"
    runtime:
      log_level: warn
      open_browser: true
```

## 五、环境变量引用机制

支持 `${VAR_NAME}` 语法引用环境变量，运行时替换：

```yaml
redis:
  password: "${REDIS_PASSWORD}"  # 从进程环境变量读取
api:
  deepseek_key: "${DEEPSEEK_API_KEY}"
```

- 如果环境变量未设置且值为字符串，报错提示
- 如果值为 `null`，跳过引用

## 六、实现方案

### 6.1 启动脚本改造

**文件**: `DeepSeekHarness/.guide/dsh-start.ps1`

```powershell
# 读取配置文件
function Read-StartupConfig {
    param([string]$EnvName)

    $projectConfig = Join-Path $DSH_ROOT ".dsh/startup.yaml"
    $userConfig = Join-Path $env:USERPROFILE ".dsh/startup.yaml"

    # 合并配置（用户级覆盖项目级）
    $config = @{}

    if (Test-Path $projectConfig) {
        $config = ConvertFrom-Yaml (Get-Content $projectConfig -Raw)
    }
    if (Test-Path $userConfig) {
        $userConfig = ConvertFrom-Yaml (Get-Content $userConfig -Raw)
        $config = Merge-Config $config $userConfig
    }

    # 应用环境覆盖
    if ($EnvName -and $config.environments.$EnvName) {
        $envOverride = $config.environments.$EnvName
        $config = Merge-Config $config $envOverride
    }

    # 替换 ${VAR} 引用
    return Resolve-EnvRefs $config
}
```

### 6.2 配置验证

启动时验证必填配置：

```powershell
function Test-StartupConfig {
    param($Config)

    $errors = @()

    if (-not $Config.dsh.root) { $errors += "dsh.root is required" }
    if (-not $Config.redis.url) { $errors += "redis.url is required" }
    if (-not $Config.dsh.patch) { $errors += "dsh.patch is required" }

    if ($errors.Count -gt 0) {
        $errors | ForEach-Object { Write-Host "[ERROR] $_" -ForegroundColor Red }
        exit 1
    }
}
```

### 6.3 环境变量注入

从配置文件读取后注入到进程环境：

```powershell
function Set-EnvFromConfig {
    param($Config)

    $env:REDIS_URL = $Config.redis.url
    $env:REDIS_PASSWORD = $Config.redis.password
    $env:REDIS_DB = [string]$Config.redis.db
    $env:REDIS_CONNECT_TIMEOUT = [string]$Config.redis.connect_timeout
    $env:REDIS_COMMAND_TIMEOUT = [string]$Config.redis.command_timeout

    if ($Config.api.deepseek_key) {
        $env:DEEPSEEK_API_KEY = $Config.api.deepseek_key
    }
}
```

## 九、扩展性设计

### 9.1 新增配置项

只需在 `startup.yaml` 中添加字段，启动脚本自动读取：

```yaml
# 未来可能的配置项
mcp:
  servers:
    - name: redis-mcp
      type: redis
      url: "${REDIS_URL}"
    - name: mysql-mcp
      type: mysql
      url: "${MYSQL_URL}"

logging:
  file: "logs/dsh.log"
  max_size: "10MB"
  max_files: 5
```

### 9.2 配置继承

支持 `extends` 语法继承基础配置：

```yaml
extends: base.yaml

redis:
  db: 2  # 覆盖基础配置的 db
```

## 十一、注意事项

1. **敏感信息**：密码、API Key 应放在用户级配置或环境变量中，不提交到 git
2. **向后兼容**：保留原有的命令行参数支持，配置文件是增量功能
3. **错误处理**：配置文件不存在时使用默认值，格式错误时明确提示
4. **性能**：配置文件在启动时一次性读取，不缓存
