## clean 策略说明（scripts/clean.ts）

`RepositoryCleaner` 采用三层安全策略：

1. **静态已知路径** — `.dsh-build/`、`.typecheck/`、根目录 `*.tsbuildinfo`
2. **构建输出目录** — 从 tsconfig `projectReferences` 递归解析每个子项目的 `outDir`，删除其父 `lib/` 目录
3. **孤儿包目录** — 无 `package.json` 的 `packages/<group>/<pkg>/` 目录，仅允许残留白名单（`node_modules`、`lib`、`.typecheck`、`*.tsbuildinfo`），未知文件触发整体拒绝删除

安全校验：每个删除目标必须在仓库边界内（`assertDescendant`）。

## 浏览器 Token 鉴权

### 机制

DSH Web 启动时自动生成一次性随机 token，通过 `?token=` 传递给浏览器，用于交换签名 cookie（HMAC，绑定 authority）。

- token 来源：`crypto.randomBytes(32)` → base64url 编码
- token 不持久化，每次进程启动刷新
- 签名 cookie 有效期：30 天（`cookieMaxAgeDays`，不可设为 0）
- cookie 属性：`host-only`、`HttpOnly`、`SameSite=Strict`、`Path=/`

### 使用流程

1. 首次访问：使用终端打印的完整 URL（带 `?token=`）
2. 浏览器拿到 cookie 后，后续直接访问 `http://127.0.0.1:3080/` 即可
3. 重启服务后 token 刷新，旧 cookie 仍有效（30 天内）

### 安全背景

决策文档：`[.agents/notes/implemented/architecture/2026-08-24-browser-token-authentication.zh.md](file:///E:/baizhoucode/companyagent/dsharness/.agents/notes/implemented/architecture/2026-08-24-browser-token-authentication.zh.md)`

> loopback HTTP 仅靠 Host header 不可信（任意请求可伪造 localhost），token 认证防止未授权调用 Host 端能力（如 `discoverModels` 泄露凭证）。

### 相关文件

| 文件                                               | 作用                                                          |
| :------------------------------------------------- | :------------------------------------------------------------ |
| `packages/client/connection/src/browser-auth.ts` | token 生成、cookie 签发、鉴权逻辑                             |

## 异常处理记录

### clean 失败：孤儿目录残留 .guide

```
clean: refusing to remove package directories without package.json; unknown entries remain:
  packages/api/.guide/1 开始.md
  packages/bundle/.guide/.dsh-bundle.path
  packages/mcp/.guide/1 开始.md
  ...
```

**原因**：`.guide/` 不在 clean 白名单内，触发第三层安全拒绝。

**解决**：将所有 `.guide/` 移至 `.guide/package/`，clean 恢复正常（removed 222 paths）。

### nvm 切换后 node/pnpm 不识别

**原因**：nvm `use` 只改写 nvm 管理的符号链接，当前 shell 的 PATH 不刷新。

**解决**：开新终端会话，或通过 `npx` 临时调用。

### token 401 Unauthorized

**现象**：直接访问 `http://127.0.0.1:3080/` 返回 401。

**原因**：DSH Web 默认要求浏览器 token 鉴权（`browser-auth.ts`），裸根路径无 cookie/无 token 触发 401。

**解决**：使用终端打印的带 `?token=` 完整 URL。
